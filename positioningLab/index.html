positioning elements

Static

default, as-is behavior

Relative

this positions a child relative to its parent. by giving an element a relative position, we can place it outside the normal flow of where it would be- but it still impacts other elements

Absolute

this takes the element out of the line up and no longer impacts elements around it, BUT you have to apply position:relative to a parent container

Fixed

positioned in relation to the browser window, it just stays put!

***Sticky***

this one is a little more advanced, and we won’t get into it yet, but perhaps challenge yourself and your project to see if you can figure it out?


Next up: z-index

this is how we control layering when we are using positioning. if an element has a position, you can add a z-index, the larger the number the closer to the top.
0=bottom 100=top
think of z-index like the “bring to front” or “send to back” in design software.

fix the footer to the bottom


I think fixed positioning is the easiest to understand as it stays in the same place the whole time. Relative positioning is when the element stays in the same flow as the rest of the document. Absolute positioning breaks that flow and does it's own thing. When I fixed the footer, it made it so it stayed in the bottom right corner the whole time, even while scrolling up and down the page. Z-index affected the page by changing the layering of each element. The higher the number, the more on top it is, and the less the number, the more on the bottom it is. I had to troubleshoot and experiment with which elements should be relative and absolute. I think using the sticky positioning on a navigation bar might be useful on my interactive sketchbook. I think I will try that out. I think positioning can become a problem if overused when the designer decides to add to many fixed elements, making the page harder to read or creating more distraction while trying to view the page in its entirety. I think also using the z-index to layer too many things could also create a hard to read page.
